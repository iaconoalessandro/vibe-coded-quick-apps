## Why this week exists
Assignment 5 loads your CSVs into SQL Server **efficiently**, and Assignment 6 pulls at least 5% of a large events table into JSON. Both use the DB-API. You learn it on `sqlite3` (no server, instant feedback), then switch the connection to `pyodbc`.

## The DB-API in 8 lines
```python
conn = sqlite3.connect(":memory:")          # pyodbc.connect(conn_str) for SQL Server
cur = conn.cursor()
cur.execute("CREATE TABLE t (id INTEGER, name TEXT)")
cur.execute("INSERT INTO t VALUES (?, ?)", (1, "O'Brien"))     # ? placeholders
cur.executemany("INSERT INTO t VALUES (?, ?)", [(2, "a"), (3, "b")])
conn.commit()                               # until now, nothing is saved
cur.execute("SELECT id, name FROM t WHERE id > ?", (1,))
rows = cur.fetchall()                       # or fetchone() / fetchmany(1000)
```
Never write `f"... VALUES ('{name}')"`. The apostrophe in O'Brien breaks it, and so does a malicious string (SQL injection).

Think about it before coding. Should the sample be **random rows**, **random posts with all their events**, or **a time window**? Each answers different questions. > **Remember**
> - `?` placeholders for values, validated identifiers for names.
> - `commit()`, or it never happened.
> - Load dimensions before facts, because of foreign keys.
> - `fast_executemany = True` on pyodbc.
> - Credentials come from the environment, never from code or git.
