## A data-quality checklist (run it on every source)
| Check | How in plain Python |
|---|---|
| completeness | count `None` / `""` / `"?"` per column (`missing_report`) |
| uniqueness | `find_duplicates(rows, ["id"])` with a set of keys |
| validity | parse types with try/except and count the failures |
| consistency | same date format? same user id in posts and users? (set differences) |
| outliers | `statistics.mean` / `stdev`, flag `abs(x - mean) > k * std` |

## Star schema refresher (see your DW book)
```text
            dim_date (date_id PK, day, month, year, season ...)
                 │
dim_store ── fact_sales ── dim_title
(store_key PK)   (store_key FK, title_key FK, date_id FK, qty)
```
1. **Grain first**: one fact row = one *what*? (one sale line; in DSS, one event).
2. **Measures**: numbers you aggregate (qty, likes).
3. **Dimensions**: descriptive context, each with an integer **surrogate key** made with a dict `natural value → id`.
4. Facts store only keys and measures. Integrity check: every FK exists in its dimension (a set subset test).

> **Remember**
> - Decide the grain before anything else.
> - `statistics.stdev` needs 2 or more values. Handle 0 and 1 explicitly.
> - Every cleaning decision goes in the report: what, how many rows, why.
> - Surrogate keys come from a dict, so a lookup costs O(1) per row.
