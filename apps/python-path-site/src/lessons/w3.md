## Why this week exists
DSS Assignment 1 hands you **CSV, XML, JSON and ARFF**, some of it large. Every reader you write should return the same shape (a list of dicts, or a generator of dicts), so cleaning and modelling never care where the data came from. This week you build those readers on the lab's census and sales files.

## Opening files the right way
```python
from pathlib import Path
path = Path("practice_data") / "jobs.csv"
with open(path, encoding="utf-8") as f:   # `with` closes the file even if an error happens
    for line in f:                         # streams line by line: fine for 10 GB
        ...
```
Always pass `encoding="utf-8"`. Otherwise the result depends on the machine (Windows VM ≠ Mac). Use `newline=""` for CSV files.

## CSV: let the module handle quotes
```python
'7066,"Rossi, Mario",5'.split(",")   # ['7066', '"Rossi', ' Mario"', '5']  <- wrong
import csv
with open(path, encoding="utf-8", newline="") as f:
    for row in csv.DictReader(f):    # {'id': '7066', 'name': 'Rossi, Mario', 'qty': '5'}
        qty = int(row["qty"])        # values are ALWAYS strings
```

## JSON maps to Python directly
`object` → `dict`, `array` → `list`, `null` → `None`, `true` → `True`. `json.load(f)` and `json.dump(obj, f, indent=2, ensure_ascii=False)`.
Many big dumps are **JSON Lines**: one object per line. Read those line by line with `json.loads(line)`.

## XML: attributes vs elements
```text
<row id="1" age="39"/>                      ← attributes: el.attrib
<census><id>1</id><age>39</age></census>    ← elements: el.findtext("age")
```
`ET.parse()` builds the whole tree in memory. For a big file, use `ET.iterparse()` and `elem.clear()` after each record. Memory stays flat, which matters for DSS events.

## ARFF
A header (`@relation`, `@attribute name type`), then `@data` and CSV-like rows. `?` means missing. Text can be quoted. **The real project file mixes quote styles and has commas and apostrophes inside text.** Build your parser on `sales.arff`, then break it on purpose with nasty test rows. Your test file is your proof.

## Exceptions: expect bad data
```python
try:
    likes = int(raw)
except ValueError:          # catch the SPECIFIC error
    likes = None            # decide, and document, what bad input becomes
```
Never use a bare `except:`. It also swallows typos and Ctrl+C.
