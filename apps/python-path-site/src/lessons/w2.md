## Lists: an ordered, changeable sequence
A **list** holds any number of values, in order, between square brackets:
```python
>>> scores = [70, 85, 92]
>>> scores[0], scores[-1]           # indexing works like strings
(70, 92)
>>> scores[1:]                      # slicing too
[85, 92]
>>> len(scores)
3
```
Unlike strings, lists **can change in place**:
```python
>>> scores.append(60)               # add at the end
>>> scores
[70, 85, 92, 60]
>>> scores[0] = 75                  # replace one item
>>> scores.remove(92)               # remove the first item equal to 92
>>> scores.pop()                    # remove and return the last item
60
>>> scores
[75, 85]
>>> scores.extend([50, 99])         # add every item of another list
>>> 85 in scores                    # membership: is it in the list?
True
```
Useful built-in functions work on any list of numbers: `sum(scores)`, `min(scores)`, `max(scores)`, `sorted(scores)`.

### Sorting: a new list or the same list
```python
>>> nums = [3, 1, 2]
>>> sorted(nums)            # returns a NEW sorted list; nums is unchanged
[1, 2, 3]
>>> nums.sort()             # sorts nums itself, and returns None
>>> nums
[1, 2, 3]
```
So `x = nums.sort()` leaves `x` equal to `None`: a classic mistake. Use `sorted()` when you want the result as a value.

To sort by something other than the value itself, pass a **key**: a function applied to each item, whose result is used for comparing.
```python
>>> words = ["banana", "fig", "apple"]
>>> sorted(words, key=len)                  # by length
['fig', 'apple', 'banana']
>>> sorted(words, key=len, reverse=True)    # longest first
['banana', 'apple', 'fig']
```
A **lambda** is a tiny function written inline: `lambda w: w[-1]` means "given `w`, return its last letter".
```python
>>> sorted(words, key=lambda w: w[-1])      # by last letter
['banana', 'apple', 'fig']
```
To sort by two things, return a tuple: Python compares the first items, and only on a tie looks at the second. To sort one of them in descending order, negate it (numbers only):
```python
people = [("Ada", 36), ("Alan", 41), ("Grace", 36)]
sorted(people, key=lambda p: (-p[1], p[0]))   # oldest first, then by name
# [('Alan', 41), ('Ada', 36), ('Grace', 36)]
```

## Tuples: a fixed group of values
A **tuple** is like a list that can't change. Use it for a fixed record where each position has a meaning:
```python
>>> point = (43.7, 10.4)            # (latitude, longitude)
>>> lat, lon = point                # unpacking: one name per position
>>> lat
43.7
>>> point[0] = 0
TypeError: 'tuple' object does not support item assignment
```
Functions return several values as a tuple: `return low, high` returns `(low, high)`, and the caller writes `low, high = f(...)`. You've already seen unpacking in `for i, city in enumerate(...)`.

## Names point at objects: aliasing
This is the one idea in this week that causes real bugs, so slow down here.

A name doesn't *contain* a list; it **points at** a list somewhere in memory. Assigning one name to another makes them point at **the same** list:
```python
a = [1, 2]
b = a           # b points at the same list as a: no copy is made
b.append(3)
print(a)        # [1, 2, 3]: there was only ever one list
```
```text
a ──┐
    ├──▶ [1, 2, 3]
b ──┘
```
To get an independent list, copy it:
```python
c = a.copy()    # or list(a), or a[:]
c.append(4)
print(a)        # [1, 2, 3]: unchanged
```
The same happens with function arguments: a function receives the caller's list, not a copy. If the function calls `.append` on it, the caller's list changes. A function that should not affect its input must copy it first, or build a new list.

Strings, numbers and tuples can't change, so with them aliasing never surprises you: every "change" makes a new object.

One more trap that follows from this: **don't add or remove items in a list while you're looping over it.** The loop skips items in confusing ways. Build a new list instead.

## Dicts: look things up by key
A **dict** (dictionary) maps **keys** to **values**. You look up a value by its key, not by position:
```python
>>> ages = {"Ada": 36, "Alan": 41}
>>> ages["Ada"]
36
>>> ages["Grace"] = 85          # add a new key, or replace an existing value
>>> "Alan" in ages              # checks the KEYS
True
>>> ages["Linus"]
KeyError: 'Linus'
>>> ages.get("Linus")           # get: None instead of an error
>>> ages.get("Linus", 0)        # or a default of your choice
0
```
Looping over a dict:
```python
for name in ages:                    # the keys
    ...
for name, age in ages.items():       # key and value together
    print(f"{name} is {age}")
list(ages.values())                  # [36, 41, 85]
```
Dicts keep keys in the order they were inserted.

Keys must be **hashable**, which in practice means unchangeable: strings, numbers and tuples work; lists don't (`TypeError: unhashable type: 'list'`). A tuple key is how you index by two things at once: `sales[("S1", 1994)] = 120`.

### Why dicts are fast
Finding something in a list means checking items one by one: for a million items, up to a million comparisons. A dict computes where a key lives from the key itself (a *hash*) and goes straight there: one step, whatever the size. Computer scientists write this as **O(n)** for the list and **O(1)** for the dict. When you have a loop over a million rows and do a lookup in each, that's the difference between a second and a day.

### Counting with a dict
The most common dict pattern: count how often each thing appears.
```python
colours = ["red", "blue", "red", "green", "red"]
counts = {}
for c in colours:
    counts[c] = counts.get(c, 0) + 1   # current count (0 if new) plus one
# {'red': 3, 'blue': 1, 'green': 1}
```
Read the key line carefully: `counts.get(c, 0)` is "the count so far, or 0 the first time", then we add 1 and store it back.

## Sets: distinct values, fast membership
A **set** holds unique values, with no order:
```python
>>> tags = {"python", "sql", "python"}
>>> tags
{'python', 'sql'}                   # the duplicate is gone
>>> set([3, 1, 3, 2])               # the quickest way to remove duplicates
{1, 2, 3}
>>> tags.add("etl")
>>> "sql" in tags                   # O(1), like a dict
True
```
Sets support the operations you know from maths:
```python
>>> a, b = {1, 2, 3}, {2, 3, 4}
>>> a & b       # intersection: in both
{2, 3}
>>> a | b       # union: in either
{1, 2, 3, 4}
>>> a - b       # difference: in a but not in b
{1}
```
The "have I seen this before?" pattern uses a set alongside a loop:
```python
seen = set()
for user in user_ids:
    if user in seen:
        print("repeat:", user)
    seen.add(user)
```
Note: `{}` is an empty **dict**. An empty set is `set()`.

### Which container?
| | written as | can change | ordered | `x in` cost | use for |
|---|---|---|---|---|---|
| list | `[1, 2]` | yes | yes | O(n) | sequences, rows |
| tuple | `(1, 2)` | no | yes | O(n) | fixed records, dict keys |
| dict | `{"a": 1}` | yes | insertion order | **O(1)** | lookup by key, grouping, counting |
| set | `{1, 2}` | yes | no | **O(1)** | distinct values, "seen before?" |

## Comprehensions: building a collection in one line
A very common loop builds a new list from an old one:
```python
squares = []
for n in range(5):
    squares.append(n * n)
```
A **list comprehension** says the same thing in one expression:
```python
squares = [n * n for n in range(5)]             # [0, 1, 4, 9, 16]
evens = [n for n in range(10) if n % 2 == 0]    # with a filter: [0, 2, 4, 6, 8]
```
Read it as: "`n * n`, for each `n` in `range(5)`". The same works for sets and dicts:
```python
{w.lower() for w in ["A", "a", "B"]}            # set: {'a', 'b'}
{w: len(w) for w in ["fig", "apple"]}           # dict: {'fig': 3, 'apple': 5}
```
Comprehensions can be nested. A comprehension *inside* another builds a list of lists:
```python
[[r * c for c in range(1, 4)] for r in range(1, 3)]   # [[1, 2, 3], [2, 4, 6]]
```
Use comprehensions for simple transformations and filters. When the logic needs several steps, a normal loop is clearer.

## A table is a list of dicts
Here is the shape you'll use for the rest of the course. One dict per row; the keys are the column names:
```python
rows = [
    {"user": "u1", "hour": 22, "likes": 10},
    {"user": "u2", "hour": 9,  "likes": 3},
    {"user": "u1", "hour": 23, "likes": 7},
]
```
Everything you'd do in SQL or a spreadsheet becomes a loop over `rows`.

**Select a column:**
```python
[r["likes"] for r in rows]                      # [10, 3, 7]
```
**Filter rows (WHERE):**
```python
[r for r in rows if r["hour"] >= 20]            # the two evening rows
```
**Group and sum (GROUP BY user, SUM(likes)):** the counting pattern, adding a value instead of 1:
```python
totals = {}
for r in rows:
    totals[r["user"]] = totals.get(r["user"], 0) + r["likes"]
# {'u1': 17, 'u2': 3}
```
**Group whole rows**, to compute several things per group later:
```python
groups = {}
for r in rows:
    groups.setdefault(r["user"], []).append(r)   # create an empty list the first time
# {'u1': [row0, row2], 'u2': [row1]}
```
**Join two tables** on a shared key. The slow way loops over both tables (for every row in one, scan all rows in the other). The fast way first builds a dict from one table, so each lookup is O(1):
```python
users = [{"user": "u1", "city": "Pisa"}, {"user": "u2", "city": "Lucca"}]
city_of = {u["user"]: u for u in users}         # index: user -> row
joined = []
for r in rows:
    match = city_of.get(r["user"])
    if match is not None:                       # inner join: skip rows without a match
        joined.append({**r, **match})           # merge two dicts into a new one
```
`{**a, **b}` makes a new dict with all keys of `a`, then all keys of `b`.

### Two helpers from the collections module
These save typing once you understand the plain-dict versions above:
```python
from collections import Counter, defaultdict

Counter(r["user"] for r in rows)          # Counter({'u1': 2, 'u2': 1})
Counter("mississippi").most_common(2)     # [('i', 4), ('s', 4)]

by_user = defaultdict(list)               # missing keys start as an empty list
for r in rows:
    by_user[r["user"]].append(r)
```

## Recursion
A function is **recursive** when it calls itself. That sounds circular, but it works when each call handles a **smaller** version of the problem, and there's a **base case** small enough to answer directly.

Example: the sum of a list is "the first item plus the sum of the rest", and the sum of an empty list is 0.
```python
def total(nums):
    if not nums:                    # base case: nothing left
        return 0
    return nums[0] + total(nums[1:])   # one item + the same problem, one item shorter
```
Trace `total([4, 5, 6])`:
```text
total([4, 5, 6]) = 4 + total([5, 6])
                       = 5 + total([6])
                             = 6 + total([])
                                   = 0
                 = 4 + 5 + 6 + 0 = 15
```
Every recursive function needs both parts. Without a base case, or if the problem doesn't get smaller, it calls itself forever, and Python stops it after about 1000 levels with `RecursionError`.

Recursion shines on data that **contains smaller copies of itself**: folders inside folders, lists inside lists, the two halves of a sorted list.
```python
def count_files(folder):            # folder = {"files": [...], "subfolders": [folder, ...]}
    n = len(folder["files"])
    for sub in folder["subfolders"]:
        n += count_files(sub)       # each subfolder is the same problem, smaller
    return n
```
For plain long sequences, a loop is better: it's faster and has no depth limit. The P4DS exam always includes one recursive function, so practise the shape: base case first, then the smaller call.

> **Remember**
> - `b = a` doesn't copy. `a.copy()` does.
> - `sorted(x)` returns a new list; `x.sort()` changes `x` and returns `None`.
> - Need "have I seen this?" inside a loop? Use a **set** or a **dict**, never a list.
> - `d[k]` raises KeyError for a missing key; `d.get(k, default)` doesn't.
> - Dict keys must be unchangeable: tuples yes, lists no.
> - Join = index one table in a dict, loop over the other.
> - Recursion = a base case + a call on a smaller problem.
