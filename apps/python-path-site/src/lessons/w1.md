## What this week is for
Every program you'll write in this course, from a CSV reader to a database loader, is built from five things: **values**, **names**, **conditions**, **loops** and **functions**. This week covers each one from zero, with examples you can type and run. The goal is fluency: by Friday, writing a loop with a condition inside should take you seconds, not minutes.

The best way to read this lesson is with a terminal open. Type `python` (in your activated venv) to start the **interactive prompt**, shown as `>>>`. Anything you type there runs immediately and shows its result. Try every example; change it; break it on purpose. Type `exit()` to leave.

## Values and their types
Every piece of data in Python is a **value**, and every value has a **type** that decides what you can do with it.
```python
>>> 42          # int: a whole number
42
>>> 3.5         # float: a number with a decimal point
3.5
>>> "Pisa"      # str: text, in single or double quotes
'Pisa'
>>> True        # bool: True or False (capital T and F)
True
>>> None        # NoneType: "no value here"
>>> type(3.5)
<class 'float'>
```
`None` deserves a mention: it means "nothing", and it shows up a lot in real data for missing values. It's not `0` and not `""`; it's its own thing.

### Arithmetic
```python
>>> 7 + 2, 7 - 2, 7 * 2
(9, 5, 14)
>>> 7 / 2       # true division: ALWAYS gives a float
3.5
>>> 7 // 2      # floor division: the whole part, rounded down
3
>>> 7 % 2       # modulo: the remainder of 7 // 2
1
>>> 2 ** 10     # power
1024
```
`%` is more useful than it looks. `n % 2` is `0` when `n` is even and `1` when it's odd. `n % 10` is the last digit of `n`. `n // 10` is `n` without its last digit.

Floats are stored in binary, so some decimals can't be exact:
```python
>>> 0.1 + 0.2
0.30000000000000004
```
This isn't a Python bug; every language does it. Never compare floats with `==` when they come from calculations: round them, or check that the difference is tiny.

### Converting between types
```python
>>> int("42")       # text to int
42
>>> float("2.5")
2.5
>>> str(7)          # number to text
'7'
>>> int("4.2")      # not a whole number: error
ValueError: invalid literal for int() with base 10: '4.2'
>>> "3" + 4         # Python never converts silently
TypeError: can only concatenate str (not "int") to str
```
This matters immediately in week 3: everything you read from a file is a string, even `"42"`, and you have to convert it on purpose.

## Names (variables)
A **name** is a label you attach to a value with `=`:
```python
qty = 5
price = 12.5
total = qty * price     # Python computes the right side first, then attaches the name
print(total)            # 62.5
```
`=` means "make this name refer to this value", not "is equal to". That's why this line makes sense:
```python
qty = qty + 1           # take the current qty (5), add 1, attach the name qty to the result (6)
qty += 1                # the same thing, shorter
```
Names are case-sensitive (`qty` and `Qty` are different), can contain letters, digits and `_`, and can't start with a digit. By convention Python uses `lower_case_with_underscores`.

## Strings
A string is a sequence of characters. Each character has a position called an **index**, starting at **0**:
```text
 s =   " P  y  t  h  o  n "
index:   0  1  2  3  4  5
from end:-6 -5 -4 -3 -2 -1
```
```python
>>> s = "Python"
>>> s[0]            # first character
'P'
>>> s[-1]           # negative indexes count from the end
'n'
>>> len(s)          # number of characters
6
```
### Slicing: taking a piece
`s[start:stop]` gives the characters from `start` up to **but not including** `stop`:
```python
>>> s[0:2]
'Py'
>>> s[2:]           # from index 2 to the end
'thon'
>>> s[:3]           # from the start to index 3 (excluded)
'Pyt'
>>> s[::-1]         # a third number is the step; -1 walks backwards
'nohtyP'
```
"Stop is excluded" seems odd at first, but it means `s[:3] + s[3:]` is always the whole string, and `s[a:b]` always has `b - a` characters.

### Methods: things a string can do
A **method** is a function that belongs to a value, called with a dot:
```python
>>> name = "  ada LOVELACE "
>>> name.strip()            # remove spaces at both ends
'ada LOVELACE'
>>> name.lower(), name.upper()
('  ada lovelace ', '  ADA LOVELACE ')
>>> name.strip().title()
'Ada Lovelace'
>>> "a,b,c".split(",")      # cut into a list at each comma
['a', 'b', 'c']
>>> "  two   words ".split()   # no argument: cut at any run of spaces, drop the empty bits
['two', 'words']
>>> "-".join(["a", "b", "c"])  # the opposite of split: glue a list together
'a-b-c'
>>> "data" in "big data"       # is one string inside another?
True
>>> "abc".startswith("a"), "x1".isalpha(), "42".isdigit()
(True, False, True)
```
**Strings never change.** A method like `upper()` doesn't modify the string; it returns a **new** one. If you don't keep it, it's gone:
```python
s = "data"
s.upper()           # creates "DATA" and throws it away
print(s)            # data
s = s.upper()       # keep the new string by attaching the name to it
print(s)            # DATA
```
### f-strings: putting values inside text
Put an `f` before the quotes, and anything inside `{ }` is computed and inserted:
```python
>>> store, qty, price = "S1", 5, 12.5
>>> f"{store}: {qty} x {price} = {qty * price}"
'S1: 5 x 12.5 = 62.5'
>>> f"{price:.2f}"          # after the colon: a format. .2f = 2 decimals
'12.50'
>>> f"[{qty:4d}]"           # 4d = an integer, right-aligned in 4 characters
'[   5]'
```

## Booleans and conditions
A **comparison** produces `True` or `False`:
```python
>>> 5 > 3, 5 == 3, 5 != 3, 5 >= 5
(True, False, True, True)
>>> 0 <= 7 <= 10            # chained: is 7 between 0 and 10?
True
```
Note `==` (compare) versus `=` (attach a name). Mixing them up is the most common beginner typo.

Combine comparisons with `and`, `or`, `not`:
```python
>>> age = 25
>>> age >= 18 and age < 65
True
>>> not (age > 30)
True
```
### if / elif / else
`if` runs a block of code only when a condition is true. The block is the **indented** lines under it; indentation is part of Python's grammar, always 4 spaces:
```python
temperature = 31
if temperature > 30:
    print("hot")            # runs only if the condition is True
    print("drink water")    # still inside the if: same indentation
print("done")               # back at the left edge: always runs
```
With several cases, Python checks them **from top to bottom and runs only the first true one**:
```python
if temperature > 30:
    label = "hot"
elif temperature > 15:      # only checked if the first condition was False
    label = "mild"
else:                       # runs if nothing above was True
    label = "cold"
```
Because only the first match runs, **order matters**. If you check `temperature > 15` first, then 35 is labelled "mild", because 35 > 15 is also true and Python never reaches the "hot" branch. When ranges overlap, put the most specific (or the highest threshold) first.

### Truthiness
`if` doesn't need a real `True`/`False`. Python treats these as false: `0`, `0.0`, `""` (empty string), `[]`, `{}`, and `None`. Everything else counts as true. So:
```python
name = ""
if not name:                # catches "" and None in one go
    print("name is missing")
```
Careful: `bool("False")` is `True`, because it's a non-empty string.

## Loops
### for: do something for each item
A `for` loop takes the items of a sequence one by one, attaches a name to each, and runs the block:
```python
for letter in "abc":
    print(letter)           # a, then b, then c

for word in ["red", "green"]:
    print(word.upper())     # RED, then GREEN
```
To repeat something a number of times, loop over `range`:
```python
>>> list(range(5))          # 0 up to 5, excluded (like slicing)
[0, 1, 2, 3, 4]
>>> list(range(2, 6))       # from 2 up to 6, excluded
[2, 3, 4, 5]
>>> list(range(0, 10, 3))   # step 3
[0, 3, 6, 9]
```
When you need the position **and** the item, use `enumerate`:
```python
for i, city in enumerate(["Pisa", "Lucca"]):
    print(i, city)          # 0 Pisa, then 1 Lucca
```
### while: repeat until something changes
A `while` loop repeats as long as its condition is true. Use it when you **don't know in advance** how many steps it will take:
```python
balance = 100
years = 0
while balance < 200:        # checked before every round
    balance = balance * 1.07
    years += 1
print(years)                # 11: how many years at 7% to double the money
```
If the condition never becomes false, the loop never ends. Something inside the loop must move towards the exit (here, `balance` grows). Press Ctrl+C to stop a runaway program.

`break` leaves a loop immediately; `continue` skips to the next round.

### The accumulator pattern
Most loops you'll write this week follow one shape: start a result, update it for each item, use it after the loop.
```python
def count_long_words(text):
    count = 0                       # 1. start the accumulator
    for word in text.split():       # 2. loop over the pieces
        if len(word) > 3:           # 3. decide whether this item matters
            count += 1              # 4. update
    return count                    # 5. after the loop (not indented under for!)
```
Trace it by hand with `"the quick brown fox"`: `count` goes 0 → 0 ("the") → 1 ("quick") → 2 ("brown") → 2 ("fox"), and the function returns 2.

The same shape builds strings (`result = ""`, then `result += ...`) and lists (`result = []`, then `result.append(...)`).

The classic bug is indenting `return` one level too far, inside the loop. Then the function returns after the **first** item, every time.

## Functions
A **function** packages a piece of code under a name, so you can run it with different inputs:
```python
def vat_price(net, rate=0.22):
    """Return the price including VAT."""
    return net * (1 + rate)
```
- `def` starts the definition; `vat_price` is the name; `net` and `rate` are **parameters**, the names the inputs get inside the function.
- `rate=0.22` is a **default value**: if the caller doesn't give a rate, it's 0.22.
- The text in triple quotes is the **docstring**: a description for humans. Every exercise's docstring is its specification.
- `return` sends a value back to whoever called the function, and **ends the function immediately**.

Calling it:
```python
>>> vat_price(100)              # rate takes its default
122.0
>>> vat_price(100, 0.10)        # or give it explicitly
110.00000000000001
>>> vat_price(100, rate=0.04)   # by name: clearer when there are several parameters
104.0
```
### return versus print
This confuses almost everyone at the start. `print` **shows** a value to a human, on the screen. `return` **gives** a value to the code that called the function, so it can be stored, compared or used in a calculation.
```python
def shout_print(word):
    print(word.upper())

def shout_return(word):
    return word.upper()

a = shout_print("hi")       # shows HI on screen, but a is None
b = shout_return("hi")      # shows nothing, but b is "HI"
```
A function with no `return` returns `None`. Tests check what you **return**, so in the exercises, never `print` the answer; `return` it.

### Returning early
Because `return` ends the function, you can leave as soon as you know the answer:
```python
def has_negative(numbers):
    for n in numbers:
        if n < 0:
            return True         # found one: no need to look further
    return False                # only reached if the loop finished without finding one
```

## Errors on purpose: raise and try
Sometimes the right thing for a function to do is refuse bad input. `raise` stops the function with an error:
```python
def percent(part, whole):
    if whole <= 0:
        raise ValueError("whole must be positive")
    return part / whole * 100
```
The opposite side is `try` / `except`: try something that might fail, and decide what happens if it does.
```python
text = "4.2"
try:
    n = int(text)           # raises ValueError
except ValueError:
    n = None                # we land here instead of crashing
```
