## 1. MBA model — 8,000 frozen profiles

`tests/fixtures/mba-golden.json` holds the MBA scorer's outputs for 8,000 seeded
pseudo-random profiles, frozen before the model was restructured into its current
data-driven form. `tests/mba-test.js` replays every profile against the current code and
requires an exact match, in both modes, on the base score and all eight individually
modelled schools. For the first 250 it also compares every breakdown line, school note,
suggested improvement, verdict and the completeness figure.

Profiles are stored as answer positions rather than option ids, so the fixture stays valid
if ids are renamed. They were generated by picking a random option in each radio group
(leaving ~20% unanswered), ticking each checkbox with probability 0.35, and setting the
employer prestige field 60% of the time.

```
8000/8000 profiles match the frozen scores (as published).
8000/8000 profiles match the frozen scores (corrected).
```

Comparison is on the exact rounded values (four decimal places), nine numbers per profile
in each of two modes — roughly 144,000 individual assertions.

### The `file://` icon bug

Worth recording because every check above had missed it. The icons were originally CSS
masks (`mask-image: url(../img/mark-gate.svg)`). Over `http://localhost` they were
perfect. Opened the way the README actually tells you to open the site — by
double-clicking `index.html` — they drew nothing: Chrome treats a mask image as a
cross-origin resource, and under `file://` each document is its own opaque origin, so the
mask resolved to empty and left correctly-sized blank boxes.

Nothing errored, nothing appeared in the console, and the layout was unchanged, which is
why serving the site over http hid it completely. The fix was to inline the SVG into the
markup; there is now no `url(../img/...)` reference anywhere in `css/app.css`:

```
grep -c 'url(\.\./img/' css/app.css  →  0
```

## 17. Per-school weighting (`tests/profiles-test.js`, 21/21)

The claim under test is narrow: a selection profile **redistributes** emphasis and does
not hand anyone points.

```
every profile renormalises to the track total ....................... all 18 combinations
the balanced profile is byte-identical to the track weighting ................... exact
an unknown profile id falls back to balanced rather than throwing ............... pass
```

Direction, using two mirror-image profiles on the management track:

| Applicant | Numbers-led school | Holistic school |
|---|---|---|
| Top 5% grades, 760 GMAT, no internships, no leadership, weak essays | **81.9** | 45.1 |
| Median grades, 590 GMAT, strong internships, national leadership, strong essays | 54.9 | **83.9** |

And the control: an evenly balanced applicant spans only **6.6 points** across all six
profiles, against **36.8** for the lopsided one — five and a half times as wide. That is
the property that keeps the calibrated thresholds meaningful.

Also checked:

- A school that takes no reference letters awards **0** for strong ones, while a holistic
  one awards the full modifier. Modifier scaling is part of the weighting, not an
  afterthought.
- Every one of the 43 schools names a defined profile and carries a `because` string
  explaining what the assignment rests on. No profile is defined and left unused.
- Bocconi MSc Finance scores the numbers-only applicant **18.7 above** the headline
  figure (83.6 against 64.9); HEC MSc International Finance scores the same answers
  **8.6 below** it (56.3). The reported shift matches the difference of the two scores
  exactly.
- The **advice is recomputed per school**: the top suggestions at Bocconi and at HEC are
  different lists, and the holistic school suggests the soft factors the applicant is
  missing. Every claimed gain, across every school in the track, was re-derived by
  actually applying the change and rescoring under that school's own weighting — 
  agreement within 0.1 points throughout.
- A hard rule still blocks regardless of how well the weighting suits you: the 4-year
  applicant stays ineligible at LBS MFA no matter which profile scores best.

### Two scoring bugs the targeted tests missed

The per-gate tests above all passed while the model was still wrong, because each one
checked a gate against a profile designed to fail it. What caught the bugs was asking the
opposite question — *is anyone blocked who obviously should not be?*

**Prerequisite rules were counted in the wrong place.** `minModules` searched only the
computing-modules question, but prerequisite rules cross freely into mathematics —
Edinburgh names "calculus, linear algebra, discrete mathematics and probability" in one
breath. Any rule naming mathematics modules therefore counted zero matches and fired
against everybody. An applicant who had passed every module on both questions was ruled
out of five programmes.

**One rule could not be satisfied by anyone.** KTH's gate demanded two modules from a list
naming one — "algorithms and data structures", which is a single option in this model. No
possible answer cleared it.

Both are now asserted directly: a maximal applicant must be blocked nowhere on any track,
and no `minModules` rule may demand more modules than it names.

## 19. What applicants reported, and the bar it has to clear

The honesty constraint of this track is a sample-size rule, and it is asserted rather than
merely documented:

```
no programme carries a grade distribution below 40 reports ...................... pass
no grade distribution rests on fewer than 20 accepted grades .................... pass
pooled tier figures clear the same two bars .................................... pass
every evidence key matches a real programme id, every tier reference resolves ... pass
```

Coverage was measured directly against the live survey **before** the collector was
written, and the collector re-checks itself against those numbers so a filter that
silently stops matching is visible rather than invisible:

| Institution | Reports since Jan 2021 | Accepted grades behind it | Grade block? |
|---|---|---|---|
| ETH Zürich | 340 | 120 | yes |
| EPFL | 72 | 25 | yes |
| Oxford | 54 | 9 | **no — fails the second bar** |
| Cambridge | 33 | — | no |
| Imperial, UCL, Edinburgh | 23 each | — | no |
| TU Delft | 20 | — | no |
| KTH | 17 | — | no |
| Amsterdam | 15 | — | no |
| everything else | 0–7 | — | no |

Two institutions out of eighteen clear both bars. Oxford is why there are two: it passes
the report threshold easily and still has only nine accepted grades behind any median that
could be drawn, so it publishes timing and nothing about grades.

For the sixteen without a figure of their own, the interface says so in those words, shows
the decision-date distribution — which needs no inference and is informative at twenty
reports — and offers the pooled figure for comparable programmes, labelled as a group
pattern rather than that programme's bar.

The pools are worth reading on their own. In the most selective UK pool (110 reports),
accepted applicants reported a median of 3.95 and rejected ones 3.86. The two outcomes are
barely separated by grades at all — which is a finding, not a gap in the data.

### Two bugs this found

**Pagination.** The survey accepts a `page` parameter and silently ignores it — it
paginates by cursor. The first version of the collector fetched page 1 of Computer Science
181 times and cached it as 181 distinct pages. Caught by checking that consecutive cached
pages had different first rows, which they did not. The collector now follows
`meta.next_cursor`, and resumes from the cursor stored with the last page written.

**Institution aliases.** EPFL, TU Delft, TUM, RWTH and Saarland all appeared to have zero
computing results. Three of them did not: EPFL is filed as "Ecole Polytechnique Federale
de Lausanne" (69 records), TU Delft as "Delft University of Technology" (20), and TUM is
split across at least four spellings. Institution names are user-supplied, so every
institution is queried under each alias worth trying and the results merged.

## Known limitations

- Cross-scale GMAT / Focus / GRE conversion is a percentile approximation, not an
  official concordance.
- Master's score thresholds are calibration. No school publishes one.
- Which selection profile a school belongs to is my reading of its published process, not
  a formula any school states. The reading is printed under every programme so it can be
  argued with; the multipliers themselves are calibration.
- Several master's data points are third-party and tagged as such in the interface.
- The IT track carries **no** estimated admitted-score distributions, because there were no
  published medians to anchor them to. Its score thresholds are pure calibration.
- Applicant-reported outcomes are a self-selected sample and are not acceptance rates. They
  cover an institution's computing master's as a whole, not individual courses.
- Several IT entry rules are tagged `programme doc` rather than `programme`: Oxford's site
  and WhatDoTheyKnow both refuse automated requests, so figures that exist officially —
  including UK FOI disclosures of applications and offers by MSc course — were not read at
  source and are not claimed as verified.
